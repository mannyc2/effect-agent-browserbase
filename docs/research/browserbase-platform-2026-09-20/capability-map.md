# Capability map and current architecture assessment

Baseline: [`1b3e9b1916621d036f2568c821e83bed72400f9c`](https://github.com/mannyc2/effect-agent-browserbase/commit/1b3e9b1916621d036f2568c821e83bed72400f9c). Provider contract: [platform research](platform.md), official SDK [v2.20.0](https://github.com/browserbase/sdk-node/tree/v2.20.0/src/resources), Playwright [v1.63.0](https://github.com/microsoft/playwright/tree/v1.63.0/docs/src/api).

**Classification.** Complete means the stated bounded workflow has a public implementation and corresponding repository test evidence; it does not mean every Browserbase variant was tested here. Partial means a material step or guarantee is missing. Inaccessible means the connected automation layer has a mechanism but consumers cannot reach it through this package. Absent means no modeled implementation. Outside scope means deliberately not a requirement of this integration. Source inspection, committed test assertions, historical execution reports and new execution are different evidence levels. **No package or hosted tests were run during this review.**

## 1. Provider resources and session configuration

| Workflow/capability | Current support and trace | Evidence and practical consequence | Recommendation / value |
| --- | --- | --- | --- |
| Allocate, connect, operate, release an execution-owned session | **Complete for the bounded path.** `BrowserbaseInteractiveHost.acquire/open` → `acquireSession` → `Provider.create` → private Playwright connector; reference retained before connect. | [Host](../../../packages/platform-browserbase/src/InteractiveBrowser.ts), [session owner](../../../packages/platform-browserbase/src/internal/Session.ts), [ownership tests](../../../packages/platform-browserbase/test/fixtures/OwnershipCases.ts). A failed connection still has an identity to release. | Preserve this default convenience workflow. High value; do not replace it with SDK calls lacking the owner. |
| Pass general launch settings | **Partial.** Public `recordSession`, `keepAlive`, `context`, viewport reach the request. No upstream-shaped launch envelope. | [Provider.create](../../../packages/platform-browserbase/src/internal/Provider.ts) hard-codes `proxies:false`, `logSession:false`, `solveCaptchas:false`; region, extension, identity settings and caller metadata cannot reach the POST. | Add a provider-faithful launch model with explicit ownership-reserved fields. Very high value: enables ordinary Browserbase environments rather than one fixed profile. |
| Recording/privacy defaults | **Partial but intentional.** Recording defaults off; logging and solving are always off, not merely defaulted off. | [InteractiveOptions](../../../packages/platform-browserbase/src/InteractiveBrowser.ts); compare [provider defaults](https://github.com/browserbase/sdk-node/blob/v2.20.0/src/resources/sessions/sessions.ts), which are not identical. A consumer cannot opt into debugging logs or CAPTCHA solving. | Keep privacy-sensitive defaults for backward compatibility; expose named opt-ins and report the effective settings. Do not silently inherit changed provider defaults. |
| Provider timeout versus execution budget | **Partial.** Provider seconds are derived from `maxElapsedMillis`, clamped to 60–21,600; a local lifetime timer still closes the resource. | [acquireSession](../../../packages/platform-browserbase/src/internal/Session.ts). `keepAlive` does not escape the enclosing execution's expiration. | Separate remote lifetime, connection/action deadlines and agent budget. High value for supervisors, human authentication and reconnects. |
| Provider pending state | **Partial.** `SessionStatus` includes `PENDING`; create does not expose a general pending→running wait operation. | [Types](../../../packages/platform-browserbase/src/Types.ts), `Allocated` versus `Metadata` in [Provider](../../../packages/platform-browserbase/src/internal/Provider.ts). Accepting a status in a schema is not implementing admission/retry behavior. | Add bounded `waitUntilRunning` with retained identity and explicit expiry/cancellation. Never assume `PENDING` proves a provider queue. |
| Persistent Context reuse | **Partial.** Existing ID and `persist` are forwarded; persistent writes require a host lease. | [ContextLease/acquireSession](../../../packages/platform-browserbase/src/internal/Session.ts), [persistentReconnect example](../../../packages/platform-browserbase/examples/hosted.ts). Consumer must provision and remember the Context elsewhere. | First-class project-qualified Context references and create/get/delete. Very high value. |
| Context creation, naming, retrieval, deletion | **Absent.** No public Context service or provider routes. | Compare [SDK Context resource](https://github.com/browserbase/sdk-node/blob/v2.20.0/src/resources/contexts.ts) with [public exports](../../../packages/platform-browserbase/package.json). | Add minimal lifecycle operations without inventing an upstream list or flush API. Consumer owns account→Context mapping and explicit deletion. |
| Context write coordination and persistence readiness | **Partial.** Lease precedes allocation and its finalizer follows teardown; cleanup reports session termination, not data synchronization. | [Session.ts](../../../packages/platform-browserbase/src/internal/Session.ts) `contextLease`, `result`, `terminate`; [Context guide](https://docs.browserbase.com/platform/browser/core-features/contexts). Two successive jobs can still need a reuse policy after `remote:"confirmed"`. | Preserve exclusive writer admission, add persistence-evidence state, quarantine and pluggable reuse verification. Highest correctness priority in Context work. |
| Context profile import/export through old upload URLs | **Outside scope: provider no longer supports uploads.** | [Current SDK deprecation](https://github.com/browserbase/sdk-node/blob/v2.20.0/src/resources/contexts.ts) says the URL is a non-functional sentinel. | Explicitly reject obsolete recipes; do not implement them merely because fields still type-check. |
| Regions, managed/external proxies and ordered routing | **Absent.** `proxies:false`; no region or proxy settings field. | Compare [session request](https://github.com/browserbase/sdk-node/blob/v2.20.0/src/resources/sessions/sessions.ts) with [Provider.create](../../../packages/platform-browserbase/src/internal/Provider.ts). | High-value launch pass-through, preserving ordering, credentials, region and geography distinctions. No proxy client should be invented inside the adapter. |
| Verified and OS identity profiles | **Absent**, with a behavioral conflict: viewport is always materialized by the wrapper. | [Verified constraints](https://docs.browserbase.com/platform/identity/verified-customization), [host defaults](../../../packages/platform-browserbase/src/InteractiveBrowser.ts). | Add provider-managed viewport mode and reject incompatible resize/setup. A boolean flag alone is insufficient. High value. |
| CAPTCHA selectors/solver, ad blocking, TLS settings | **Absent.** Native page operations do not compensate for missing provider launch settings. | [BrowserSettings](https://github.com/browserbase/sdk-node/blob/v2.20.0/src/resources/sessions/sessions.ts). | Expose upstream names and bounded failure semantics. CA references preferred to unrestricted certificate-error bypass. Medium/high value depending on target sites. |
| Allowed domains / framework network policies | Provider navigation filter **absent**; `ExactHosts` and `PublicWeb` **intentionally unsupported**. | [Public policy validation](../../../packages/platform-browserbase/src/InteractiveBrowser.ts); [SDK allowedDomains semantics](https://github.com/browserbase/sdk-node/blob/v2.20.0/src/resources/sessions/sessions.ts). Main-frame plus subdomains is not exact-host, whole-browser containment. | Expose `allowedDomains` honestly; retain rejection of unprovable framework policies. Do not represent routing hooks as a security sandbox. |
| Extension upload/reference/delete | **Absent.** No extension launch field or resource service. | [Extension guide](https://docs.browserbase.com/platform/browser/core-features/browser-extensions) and provider request above. | First-class uploaded extension reference plus bounded upload/delete; load at session creation, not via a second connection. High value for customization. |
| Project CA certificate resources | **Absent.** | [SDK resources](https://github.com/browserbase/sdk-node/tree/v2.20.0/src/resources) and `proxySettings.caCertificates` in session types. | Reference pass-through first; CRUD as small administrative service later. Medium value for enterprise traffic. |
| Project metadata, usage, quota and admission | **Absent** beyond translated HTTP errors. | [HTTP status handling](../../../packages/platform-browserbase/src/internal/Http.ts) knows `429` and retry-after; no shared scheduler or usage service. | Add passive inspection and an optional consumer admission port, not a mandatory job scheduler or hard-coded plan table. |
| Caller metadata and recovery search | **Partial.** An allocation nonce is sent under `effectAgentAttempt`; no public list/query and caller metadata is not accepted. | [Provider.create](../../../packages/platform-browserbase/src/internal/Provider.ts); [Session list query](https://github.com/browserbase/sdk-node/blob/v2.20.0/src/resources/sessions/sessions.ts). | Expose bounded listing/query and reserve a namespaced internal metadata key. High value for uncertain allocation and operator diagnosis. A nonce is not idempotency. |

## 2. Connection, automation and customization

| Workflow/capability | Current support and evidence | Recommendation / value |
| --- | --- | --- |
| Intentional detach then reconnect | **Complete within the original live owner scope.** Requires `keepAlive`, stored target ID and operator acknowledgement; reconstructs driver and fresh observation. [Session reconnect](../../../packages/platform-browserbase/src/internal/Session.ts). | Keep, but document its scope. Do not advertise it as crash/process recovery. |
| Attach to an existing session from a fresh process | **Absent.** Public host has no `attach(reference)`; `reconnectTarget` exists only in the old owner closure. | High value: separate remote-resource ownership from local connection ownership and add explicitly borrowed attachment. |
| Recovery after unexpected disconnection | **Partial.** Owner is fenced `uncertain`; reconnect admits detached/acquiring phases, not arbitrary uncertain state. | Add a recovery assessment, not blind replay. New connection can establish current state; it cannot establish the result of a previous click. |
| Cooperative Live View handoff | **Complete for cooperative authorization.** Pause before issuing URL; acknowledgement/token and fresh observation before resuming. [Session](../../../packages/platform-browserbase/src/internal/Session.ts), [ownership cases](../../../packages/platform-browserbase/test/fixtures/OwnershipCases.ts). | Preserve. Clarify token is local handoff coordination, not proof that all external clients relinquished control. |
| Native browser ownership and injectable binding | **Inaccessible through public API.** Strict provider connector and test construction seams are private. [Playwright](../../../packages/platform-browserbase/src/internal/Playwright.ts), [Driver](../../../packages/platform-browserbase/src/internal/Driver.ts). | Public trusted binding composition, not a `cdpUrl` supplied by an agent. Keep production endpoint checks. High value for testability/customization. |
| Pages, frames, selection, observed-node actions | **Complete for modeled controls.** Explicit page/frame selection, exact element evidence, bounded reads and stale-handle fencing. [Types](../../../packages/platform-browserbase/src/Types.ts), [Session](../../../packages/platform-browserbase/src/internal/Session.ts). | Preserve, but add document readiness and distinguish page identity from array position. Do not rewrite good evidence fencing as generic selector retries. |
| Persistent native-context selection | **Partial by design.** Driver requires exactly one native context, adopting the default provider context. | Keep one default context as the supported contract until recording/persistence/permissions on additional native contexts are validated. Browserbase Context IDs are not native BrowserContext IDs. |
| Initialization scripts | **Inaccessible.** Pinned native API supports context-level document initialization, but public host exposes no such operation. | First-class bootstrap installed before dependent actions. Use native `addInitScript`, including its returned Disposable; do not build a second injection engine. |
| Browser→consumer service calls | **Inaccessible.** Native bindings/function exposure exist, public wrapper has no controlled registration port. | Typed, bounded, origin-checked binding registration in the connection scope. Never expose API keys, arbitrary host execution or raw service environment to the page. |
| Cookies, permission grants, geolocation, headers, routing | **Inaccessible** through the owned connection; these are native capabilities, not automatically Browserbase launch fields. | Small trusted bootstrap/runtime capabilities implemented with maintained Playwright methods. Strongly distinguish best-effort environment controls from network containment. |
| Async bootstrap and existing-page readiness | **Absent.** The native page registry manages dialogs/popups/capture but does not await consumer initialization before publishing usable pages. | Mandatory readiness barrier for configured bootstrap; explicit late-attach semantics for existing documents. Very high value for coherent customization. |
| Page suspension | **Complete for the documented opt-in subset**, not universal clock stopping. [PageControl](../../../packages/platform-browserbase/src/PageControl.ts), [PageExecution](../../../packages/platform-browserbase/src/internal/PageExecution.ts), [page tests](../../../packages/platform-browserbase/test/page-execution.test.ts). | Preserve no implicit resume and current incompatible-mode checks. Prove initialization finishes before suspension; never call an unresolved readiness promise on a frozen document. |
| General raw CDP/native Browser object export | **Intentionally outside current contract.** [PR #27](https://github.com/mannyc2/effect-agent-browserbase/pull/27) and README establish this boundary. | Do not revive as a prerequisite. First-class bootstrap plus a trusted binding service addresses the actual workflows without a second unfenced client. |
| Agent toolkit | **Complete as a local extension, not proof of upstream endorsement or confinement.** [Tools](../../../packages/platform-browserbase/src/Tools.ts). | Preserve separate host authority. The [latest #4 decision](https://github.com/mannyc2/effect-agent-browserbase/issues/4#issuecomment-5751302698) accepts local divergence and moves binding composition to #6. |

## 4. What the architecture gets right

The most valuable abstraction is the **single scoped mutation owner**, not the number of wrapped Playwright methods. It retains allocation identity, fences unknown dispatch outcomes, invalidates old observations, coalesces cleanup, and separates local disconnect from provider terminal evidence. [Ownership cases](../../../packages/platform-browserbase/test/fixtures/OwnershipCases.ts) explicitly assert pre-dispatch versus post-dispatch interruption and failed release behavior. These properties should remain acceptance gates through every stage.

The split between live capabilities and serializable references is also strong. A `SessionReference` supports later artifact retrieval without pretending to be a live session. Capture uses private association rather than letting a copied object manufacture authority. A refactor should not replace that deliberate identity boundary with public mutable fields merely to reduce closure or WeakMap counts. [Capture public admission](../../../packages/platform-browserbase/src/Capture.ts), [Types](../../../packages/platform-browserbase/src/Types.ts).

The HTTP boundary intentionally avoids ambient credential/header transformations and automatic URL following. It bounds bodies and media, sanitizes failures and disables tracing at the credential-bearing boundary. Shared service composition should preserve these properties, not replace them with an unrestricted ambient HTTP client. [Http.ts](../../../packages/platform-browserbase/src/internal/Http.ts).

## 5. Where the abstraction currently loses meaning

**Configuration is coupled at the wrong level.** Account credentials, launch settings, automation defaults and finalizer callbacks live in one options object, but artifact layers expect only a strict four-field account subset. `examples/hosted.ts` passes its larger object to both kinds of layer; TypeScript permits the variable, runtime decoding rejects it. This is independently visible in source and was [reported during authorized hosted acceptance](https://github.com/mannyc2/effect-agent-browserbase/issues/6#issuecomment-5751167681). That report also records success after correcting the example. It is historical evidence, not a test executed in this review. Fix shared construction and examples before adding more fields; do not weaken strict credential validation.

**Creation collapses known rejection into uncertainty.** `Http` preserves HTTP status/retry-after classification, but `acquireSession` maps every allocation error without a known reference to `allocation-unknown`, retaining only status. A known authentication or rate-limit rejection needs different operator action from a lost POST response. `Recordings.request` already preserves this distinction for assembly: reuse the principle, not necessarily its subsystem-specific type. [Session](../../../packages/platform-browserbase/src/internal/Session.ts), [Recordings](../../../packages/platform-browserbase/src/Recordings.ts).

**Reconcile is not inspect; reconnect is not adopt; cleanup is not flush.** These three distinctions should become public vocabulary. The current methods are internally conservative but easy to over-read. A passive dashboard must not call a release-requesting reconciliation method. A fresh process cannot resurrect closure state. A Context consumer needs persistence visibility beyond confirmation that a remote process ended.

**Useful native mechanisms are blocked as an all-or-nothing boundary.** Consumers can implement scripts, permissions, bindings and cookies with Playwright in general, but not through this package's current public session. Telling them simply to use `page.addInitScript` is not an answer: they have no public native Page. Controlled bootstrap and binding composition are the missing layer; a second CDP connection would bypass the ownership the package is designed to provide.

**Diagnostics are rich in local outcomes but poor in cross-resource explanation.** Capture has explicit accounting and owner cleanup has useful facts, but there is no coherent journal connecting environment recipe, allocation attempt, provider session, connection generation, document readiness and artifact page. Adding that correlation unlocks supportability without exposing raw provider exceptions or browser data.

## 6. Current issue/PR context, not obsolete assumptions

The broad [#4](https://github.com/mannyc2/effect-agent-browserbase/issues/4) description contains superseded limitations. Its latest closure decision preserves the remaining binding/composition work under [#6](https://github.com/mannyc2/effect-agent-browserbase/issues/6), recognizes target-pinned capture/sizing/page control, and accepts the local Tools contract. [#7](https://github.com/mannyc2/effect-agent-browserbase/issues/7) is parked/not planned; this proposal does not require cross-provider standardization or filing upstream.

Keep the independently tracked failures distinct: [#9](https://github.com/mannyc2/effect-agent-browserbase/issues/9) backward source timestamps; [#19](https://github.com/mannyc2/effect-agent-browserbase/issues/19) insufficient native frames; [#28](https://github.com/mannyc2/effect-agent-browserbase/issues/28) intermittent page-control fixture identity/readiness. A later passing run is not a root-cause fix. The #28 proposed positional-page explanation is plausible source reasoning, not an observation established by this review. Resolve each with bounded diagnostics and independent regression evidence rather than bundling them into a broad architecture rewrite.
